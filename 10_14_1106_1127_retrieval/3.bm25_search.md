# 키워드 검색 실습

**혼다 미나코의 출생 병원은 어디인가요?**

BM25는 질문과 문서에서 일치하는 토큰을 바탕으로 점수를 매깁니다. 문서에서 자주 나오고 전체 문서에서는 드문 토큰에 더 높은 점수를 주며,<br> 문서 길이도 고려합니다.이번 실습에서는 같은 질문을 동의어를 추가했을 때 근거 청크의 순위가 어떻게 바뀌는지 확인합니다.
<br>이 외에도 여러 기법을 사용하여 키워드 검색의 순위를 조정합니다

## 1. 키워드 실습용 인덱스 준비

[ElasticSearch 파이선 실습](1.python_elasticsearch_basics.md)에서 사용한 Nori `discard`와 명사 중심 품사 필터를 사용합니다. `title`과 `text`를 색인하고, 검색할 때 사용할 분석기 두 개를 준비합니다.

| 분석기 | 용도 |
| --- | --- |
| `korean_text` | 제목과 본문 색인, 기본 검색 |
| `korean_search_synonyms` | 기본 분석에 동의어를 추가하는 검색 |

Kibana Dev Tools에서 동의어 세트를 먼저 만든 뒤 인덱스를 만듭니다. `병원 => 병원, 산원`은 질문에 `병원`이 나오면 `병원`과 `산원`을 모두 검색하는 규칙입니다. 이 규칙은 출생 장소 예제에 적용합니다. [Elasticsearch 8.19 동의어 필터](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/analysis-synonym-graph-tokenfilter.html)

동의어 세트 `rag-miracl-ko-bm25-synonyms`를 등록합니다.

```json
PUT /_synonyms/rag-miracl-ko-bm25-synonyms
{
  "synonyms_set": [
    {
      "id": "birth-hospital",
      "synonyms": "병원 => 병원, 산원"
    }
  ]
}
```

등록한 동의어 세트를 참조하는 검색 분석기를 인덱스에 설정합니다.

```json
PUT /rag-miracl-ko-bm25
{
  "settings": {
    "analysis": {
      "tokenizer": {
        "korean_tokenizer": {
          "type": "nori_tokenizer",
          "decompound_mode": "discard"
        }
      },
      "filter": {
        "noun_pos": {
          "type": "nori_part_of_speech",
          "stoptags": [
            "E", "IC", "J", "MAG", "MAJ", "MM", "NP",
            "SF", "SP", "SSC", "SSO", "SC", "SY", "SE",
            "VA", "VCN", "VCP", "VV", "VX",
            "XPN", "XR", "XSA", "XSV", "UNKNOWN", "UNA", "NA", "VSV"
          ]
        },
        "course_synonyms": {
          "type": "synonym_graph",
          "synonyms_set": "rag-miracl-ko-bm25-synonyms",
          "updateable": true
        }
      },
      "analyzer": {
        "korean_text": {
          "type": "custom",
          "tokenizer": "korean_tokenizer",
          "filter": ["noun_pos", "lowercase"]
        },
        "korean_search_synonyms": {
          "type": "custom",
          "tokenizer": "korean_tokenizer",
          "filter": ["noun_pos", "lowercase", "course_synonyms"]
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "title": { "type": "text", "analyzer": "korean_text" },
      "text": { "type": "text", "analyzer": "korean_text" }
    }
  }
}
```

국민대 저장소 루트에서 [BM25 색인 스크립트](3.index_bm25.py)를 실행합니다. [코퍼스](dataset/corpus.jsonl)의 제목과 본문 1,000건을 색인하고 원본 `docid`를 Elasticsearch의 `_id`로 사용합니다.

```powershell
uv run --python 3.12 --with 'elasticsearch>=8.19,<9' python ./10_14_1106_1127_retrieval/3.index_bm25.py
```

```json
GET /rag-miracl-ko-bm25/_count
```

## 2. 제목과 본문 검색

아래 요청으로 `multi_match`를 실행해 제목과 본문을 함께 검색합니다.

```json
GET /rag-miracl-ko-bm25/_search
{
  "size": 10,
  "_source": ["title", "text"],
  "query": {
    "multi_match": {
      "query": "혼다 미나코의 출생 병원은 어디인가요?",
      "fields": ["title", "text"],
      "analyzer": "korean_text"
    }
  }
}
```

1. 1위 청크의 `_source.text`에 혼다 미나코가 태어난 병원이나 산원의 이름이 적혀 있는지 확인합니다.
2. 혼다 미나코가 태어난 병원이나 산원의 이름이 본문에 적힌 청크가 **Top 10에서 몇 위인지** 확인합니다.

기록한 뒤 아래 요청으로 근거 청크 `64649#3`을 확인합니다. 본문에는 **나리마스 산원에서 태어났다**고 적혀 있습니다.

```json
GET /rag-miracl-ko-bm25/_doc/64649%233
```

## 3. 동의어 적용 전후 비교

아래 `_analyze` 요청을 `korean_text`와 `korean_search_synonyms`로 각각 실행합니다. 두 응답의 `tokens[].token`을 비교해 **어떤 토큰이 추가됐는지**, 원래 토큰인 `병원`도 남아 있는지 확인합니다.

- 동의어 미적용 분석
```json
POST /rag-miracl-ko-bm25/_analyze
{
  "analyzer": "korean_text",
  "text": "혼다 미나코의 출생 병원은 어디인가요?"
}
```

- 동의어 적용 분석
```json
POST /rag-miracl-ko-bm25/_analyze
{
  "analyzer": "korean_search_synonyms",
  "text": "혼다 미나코의 출생 병원은 어디인가요?"
}
```

- 동의어 사용 분석
```json
GET /rag-miracl-ko-bm25/_search
{
  "size": 10,
  "_source": ["title", "text"],
  "query": {
    "multi_match": {
      "query": "혼다 미나코의 출생 병원은 어디인가요?",
      "fields": ["title", "text"],
      "analyzer": "korean_search_synonyms"
    }
  }
}
```


2절의 `_search` 요청에서 `analyzer`를 `korean_search_synonyms`로 바꿔 실행합니다. 근거 청크 `64649#3`의 **순위가 몇 위에서 몇 위로 바뀌었는지** 기록하고, 적용 전후의 `_score`도 함께 적습니다.

Elasticsearch 8.19.21에서 코퍼스 1,000건으로 실행한 예시입니다.

| 검색 분석기 | `64649#3` 순위 | BM25 점수 |
| --- | ---: | ---: |
| `korean_text` | 5위 | 9.2761 |
| `korean_search_synonyms` | 4위 | 9.7618 |

이 요청의 `multi_match`는 제목과 본문 중 점수가 높은 필드의 점수를 사용합니다. 기본 검색에서는 제목의 `혼다`와 `미나코`가 점수를 결정해 여러 청크가 동점입니다. 동의어를 적용하면 본문의 `산원`까지 일치하면서 본문 점수가 제목 점수를 앞섭니다. 두 검색 모두 1위는 `64649#0`입니다.

## 4. 근거 청크의 순위 올리기

동의어를 적용한 검색에서 `64649#3`은 4위였습니다. 아래 두 요청을 각각 실행해 **출생 장소가 적힌 청크가 몇 위인지** 확인합니다.

### 본문의 출생 장소 표현에 가산점 주기

기존 `multi_match`를 `bool.must`에 둡니다. `bool.should`의 `match`는 본문에 `병원`이나 `산원`이 일치한 청크에 점수를 더합니다.

```json
GET /rag-miracl-ko-bm25/_search
{
  "size": 10,
  "_source": ["title", "text"],
  "query": {
    "bool": {
      "must": {
        "multi_match": {
          "query": "혼다 미나코의 출생 병원은 어디인가요?",
          "fields": ["title", "text"],
          "analyzer": "korean_search_synonyms"
        }
      },
      "should": {
        "match": {
          "text": {
            "query": "병원",
            "analyzer": "korean_search_synonyms"
          }
        }
      }
    }
  }
}
```

### 제목과 본문에 흩어진 검색어를 함께 점수에 반영하기

`multi_match`에 `"type": "cross_fields"`를 지정합니다. 같은 분석기를 쓰는 제목과 본문을 묶어 검색어별로 일치를 평가합니다. 이 질문에서는 제목의 `혼다`, `미나코`와 본문의 `출생`, `산원`이 함께 점수에 기여할 수 있습니다. [Elasticsearch 8.19 multi_match 문서](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/query-dsl-multi-match-query.html#type-cross-fields)

```json
GET /rag-miracl-ko-bm25/_search
{
  "size": 10,
  "_source": ["title", "text"],
  "query": {
    "multi_match": {
      "query": "혼다 미나코의 출생 병원은 어디인가요?",
      "type": "cross_fields",
      "fields": ["title", "text"],
      "analyzer": "korean_search_synonyms"
    }
  }
}
```

Elasticsearch 8.19.21에서 근거 청크 `64649#3`의 순위를 확인했습니다.

| 검색 방식 | `64649#3` 순위 | `_score` |
| --- | ---: | ---: |
| 동의어 적용 · 기본 `multi_match` | 4위 | 9.7618 |
| 본문 일치에 `bool.should` 가산점 | 1위 | 14.8849 |
| `multi_match`의 `cross_fields` | 1위 | 18.8477 |

`bool.should`에서는 출생 장소를 묻는 질문에 맞춰 `병원`을 강조했습니다. 동의어 규칙으로 `산원`까지 포함되어 이 예제에서는 근거 청크가 1위로 올라갔습니다. 여러 유형의 질문에 적용하려면 질문마다 어떤 단어에 가산점을 줄지 정해야 하는데, 이를 일관되게 고르기는 어렵습니다.

`cross_fields`는 검색할 때 제목과 본문을 하나의 필드처럼 묶고, 질문의 각 검색어를 두 필드에 걸쳐 평가합니다. 이 예제에서는 제목의 `혼다`, `미나코`와 본문의 `출생`, `산원`이 같은 청크의 점수에 함께 반영됐습니다.

### 번외 · 검색어 반복과 BM25 점수

키워드 스터핑이라고 아세요? 요즘은 이런 글이 잘 안 보이지만, 예전에는 검색 노출을 노린 바이럴 글에서 자주 쓰던 방식입니다. 검색에 걸릴 만한 단어를 한 줄에 나열하거나, **강남 맛집 먹방 먹방투어**처럼 같은 단어를 반복해서 넣는 거예요. [티스토리 「자매수산」](https://pricelaziness.tistory.com/148)

요즘은 네이버와 구글이 문맥과 무관한 키워드 나열이나 부자연스러운 반복을 스팸으로 탐지합니다. 스팸으로 판단되면 검색 순위가 내려가거나 결과에서 빠질 수 있습니다. 구글은 검색어와 문서가 담고 있는 의미도 비교합니다. 예를 들어 `강남맛집`을 열 번 써도, 사용자가 찾는 메뉴와 가격 정보는 그대로입니다.

불교 질문의 기본 검색 1위인 `261019#1`은 본문에 `불교`가 **9번** 나옵니다. `_explain`에서 이 토큰의 등장 횟수 `freq=9`와 본문 점수 `7.2980`을 확인할 수 있습니다. BM25는 검색어의 등장 빈도를 점수에 반영하므로, 창건자 이름이 없는 문서도 질문에 답하는 문서보다 높은 순위에 나올 수 있습니다.

## 6. SEO와 AI 검색 최적화

앞의 맛집 예시를 식당 홈페이지에 적용해 봅시다. 누군가 **“강남역 근처에서 1인 2만 원 이하로 점심을 먹을 수 있나요?”**라고 검색하면, 답에 필요한 정보는 식당의 위치, 점심 메뉴 가격, 주문 가능 시간입니다.

| 용어 | 콘텐츠를 만들 때 살펴볼 질문 |
| --- | --- |
| **SEO** (Search Engine Optimization, 검색 엔진 최적화) | 검색 엔진이 메뉴 페이지를 찾아 색인할 수 있나요? 사용자가 검색 결과에서 어떤 페이지인지 알아볼 수 있나요? |
| **AEO** (Answer Engine Optimization, 답변 엔진 최적화) | “2만 원 이하 점심 메뉴가 있나요?”에 직접 답하는 문장이 있나요? 가격과 적용 조건을 함께 읽을 수 있나요? |
| **GEO** (Generative Engine Optimization, 생성형 검색 최적화) | 생성형 AI가 여러 출처를 종합해 답할 때, 이 페이지에서 어떤 사실을 근거로 삼고 어느 페이지를 출처로 제시할 수 있나요? |

AEO와 GEO는 실무에서 겹쳐 쓰이는 용어입니다. Google은 AI Overviews와 AI Mode에도 기존 SEO 원칙이 적용된다고 설명합니다. 메뉴 페이지를 검색 엔진이 찾을 수 있게 연결하고, 가격처럼 중요한 정보는 페이지에서 읽을 수 있는 텍스트로 제공합니다. Bing은 AI 답변에 출처로 표시된 페이지와 인용 횟수를 확인할 수 있는 보고서를 제공합니다. [Google Search Central의 생성형 AI 검색 가이드](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) · [Bing Webmaster Tools의 AI Performance 안내](https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview/)

### 같은 질문에 답하는 페이지 만들기

가상의 식당 홈페이지에 두 문구가 있다고 가정합니다.

- **A** · 강남역 맛집, 강남 점심 맛집, 강남역 점심 추천
- **B** · 강남역 3번 출구에서 도보 5분입니다. 평일 11시 30분부터 14시까지 점심 정식을 1인 18,000원에 판매합니다.

B 문구에서 **2만 원 이하인지**와 **언제 주문할 수 있는지** 확인할 수 있습니다. 가격을 근거로 인용한다면 ‘평일 점심’이라는 조건도 함께 가져와야 합니다. 실제 페이지라면 이 내용을 메뉴 안내에 싣고, 가격이나 시간이 바뀔 때 갱신합니다.

### Kibana Dev Tools에서 검색 결과 하이라이트 보기

Google 검색 결과에서 제목 아래에 보이는 **스니펫**은 페이지 내용을 미리 보여 주는 짧은 설명입니다. 검색어가 강조되어 있으면 어떤 표현이 검색과 관련되는지 빠르게 볼 수 있습니다. Elasticsearch에서도 `highlight`를 요청해 검색어가 일치한 본문 일부를 응답에 함께 담을 수 있습니다. [Google 검색의 스니펫 안내](https://developers.google.com/search/docs/appearance/snippet) · [Elasticsearch 8.19 하이라이팅](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/highlighting.html)

Kibana Dev Tools의 Console에서 4절의 `cross_fields` 검색에 `highlight`를 추가해 실행합니다. 검색 점수에는 제목과 본문의 일치를 함께 반영합니다. 본문의 하이라이트는 `highlight_query`에서 `병원`과 동의어 `산원`이 일치한 구간을 기준으로 가져옵니다.

~~~json
GET /rag-miracl-ko-bm25/_search
{
  "size": 10,
  "_source": ["title", "text"],
  "query": {
    "multi_match": {
      "query": "혼다 미나코의 출생 병원은 어디인가요?",
      "type": "cross_fields",
      "fields": ["title", "text"],
      "analyzer": "korean_search_synonyms"
    }
  },
  "highlight": {
    "pre_tags": ["<em>"],
    "post_tags": ["</em>"],
    "fields": {
      "text": {
        "fragment_size": 100,
        "number_of_fragments": 1,
        "highlight_query": {
          "match": {
            "text": {
              "query": "병원",
              "analyzer": "korean_search_synonyms"
            }
          }
        }
      }
    }
  }
}
~~~
