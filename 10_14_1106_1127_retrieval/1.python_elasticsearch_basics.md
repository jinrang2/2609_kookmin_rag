## 1. Dev Tools 요청과 Python 메서드

| Kibana Dev Tools | Python | 확인할 값 |
| --- | --- | --- |
| `GET /` | `client.info()` | 서버 버전 |
| `GET /인덱스/_count` | `client.count(index=...)` | 문서 수 |
| `GET /인덱스/_search` | `client.search(index=..., body=...)` | 검색 결과 |

```python
from pprint import pprint

from elasticsearch import Elasticsearch

ES_URL = "https://localhost:9200"
ES_USERNAME = "elastic"
ES_PASSWORD = "elastic"

index = "kibana_sample_data_ecommerce"

with Elasticsearch(
    ES_URL,
    basic_auth=(ES_USERNAME, ES_PASSWORD),
    verify_certs=False,
    ssl_show_warn=False,
) as client:
    
    body = {
        "size": 3,
        "_source": ["order_id", "category"],
        "query": {
            "match": {"category": "Clothing"}
        },
    }

    response = client.search(index=index, body=body)

    hits = response["hits"]["hits"]

    for hit in hits:
        pprint(hit)

    if hits:
        doc = client.get(index=index, id=hit['_id'], source_includes=["order_id", "category"])
        print(f"조회대상 _id:{hit['_id']}")
        pprint(doc.body["_source"])

```

## 3. Nori 분석기

Nori는 Elasticsearch의 한국어 형태소 분석기입니다. 
한국어는 `병원은`, `병원에서`처럼 같은 단어에 서로 다른 조사가 붙기 때문에, 공백을 기준으로만 나누면 같은 검색어로 잡기 어렵습니다. 
Nori는 단어와 조사의 경계를 분석해 본문과 질문에서 공통으로 검색할 토큰을 만들 수 있게 해줍니다.

### Nori 설치 확인방법
- 실행
```
GET /_cat/plugins?v
```
- 결과
```
name       component     version
.....      analysis-nori 8.19.21
```


> [!NOTE]  
> 설치가 필요하면 Elasticsearch 설치 폴더에서 Windows는 `.\bin\elasticsearch-plugin.bat install analysis-nori`, 
> Linux는 `bin/elasticsearch-plugin install analysis-nori`를 실행합니다. 

클러스터의 모든 노드에 설치하고 재시작합니다. 
[Elasticsearch 8.19 Nori 설치 문서](https://www.elastic.co/guide/en/elasticsearch/plugins/8.19/analysis-nori.html)

### decompound_mode

Nori가 복합어로 인식한 단어를 어떤 토큰으로 남길지 정하는 설정입니다. 
아래는 사용자 사전 없이 `국민대`를 분석한 결과입니다.

| 설정 | `국민대`를 분석한 토큰 |
| --- | --- |
| `none` | `국민대` |
| `discard` | `국민`, `대` |
| `mixed` | `국민대`, `국민`, `대` |

일반적인 본문 검색은 대개 Nori 기본값인 `discard`로 시작합니다. 이 실습에서도 복합어를 구성 단어로 나눠 검색할 수 있도록 `discard`를 사용합니다.

제품명이나 제도명처럼 복합어 전체가 검색 단서가 될 때는 `mixed`를 사용합니다. 예를 들어 사내 규정에서 `육아휴직`을 검색할 때, Nori가 이를 복합어로 인식하면 `육아`, `휴직`과 함께 `육아휴직` 토큰도 남겨 제도명 자체를 검색에 활용할 수 있습니다.

> [!NOTE]  
> [Nori 토크나이저 설정](https://www.elastic.co/guide/en/elasticsearch/plugins/8.19/analysis-nori-tokenizer.html)


### 명사 중심 검색을 위한 `stoptags`

**“수강 정정 기간은 언제인가요?”**에서 검색할 말을 고르면 **수강 정정 기간**입니다. 이 실습은 질문과 문서에 공통으로 등장하는 이름과 주제를 찾는 BM25 검색이므로, 명사 중심으로 토큰을 남깁니다. 날짜, 문서 번호, 영문 명칭에도 대응하도록 숫자와 외국어·한자 토큰을 함께 남깁니다.

```http
POST /_analyze
{
  "tokenizer": "nori_tokenizer",
  "text": "수강 정정 기간은 언제인가요",
  "explain": true,
  "attributes": ["leftPOS"]
}
```

`detail.tokenizer.tokens`에서 `수강`, `정정`, `기간`이 일반 명사(`NNG`)로 분석되는지 확인합니다.

| 남길 토큰 | 품사 태그 |
| --- | --- |
| 일반·고유·의존 명사 | `NNG`, `NNP`, `NNB`, `NNBC` |
| 명사 파생 접미사 | `XSN` |
| 수사와 숫자 | `NR`, `SN` |
| 외국어와 한자 | `SL`, `SH` |

`stoptags`는 **제거할 품사 목록**이므로 위 표의 태그는 목록에서 뺍니다. 아래 목록은 Nori의 기본 목록을 교체합니다. [Nori 품사 필터 문서](https://www.elastic.co/guide/en/elasticsearch/plugins/8.19/analysis-nori-speech.html)

```http
POST /_analyze
{
  "tokenizer": "nori_tokenizer",
  "filter": [
    {
      "type": "nori_part_of_speech",
      "stoptags": [
        "E", "IC", "J", "MAG", "MAJ", "MM", "NP",
        "SF", "SP", "SSC", "SSO", "SC", "SY", "SE",
        "VA", "VCN", "VCP", "VV", "VX",
        "XPN", "XR", "XSA", "XSV", "UNKNOWN", "UNA", "NA", "VSV"
      ]
    }
  ],
  "text": "수강 정정 기간은 언제인가요"
}
```

결과로 `수강`, `정정`, `기간`이 남습니다. 

### 인덱스에 Nori 적용
`settings.analysis`에서 분석기를 정의하고, 
`mappings.properties`에서 어떤 필드가 그 분석기를 쓰는지 지정합니다. 

```json
PUT /rag-nori-nouns-kibana
{
  "settings": {
    "analysis": {
      "tokenizer": {
        "korean_tokenizer": {
          "type": "nori_tokenizer",
          "decompound_mode": "discard"
        }
      },
      "filter": {
        "noun_pos": {
          "type": "nori_part_of_speech",
          "stoptags": [
            "E", "IC", "J", "MAG", "MAJ", "MM", "NP",
            "SF", "SP", "SSC", "SSO", "SC", "SY", "SE",
            "VA", "VCN", "VCP", "VV", "VX",
            "XPN", "XR", "XSA", "XSV", "UNKNOWN", "UNA", "NA", "VSV"
          ]
        }
      },
      "analyzer": {
        "korean_text": {
          "type": "custom",
          "tokenizer": "korean_tokenizer",
          "filter": ["noun_pos", "lowercase"]
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "docid": { "type": "keyword" },
      "title": { "type": "text", "analyzer": "korean_text" },
      "text": { "type": "text", "analyzer": "korean_text" }

  }

```

### Python에서 같은 요청 보내기

앞에서 만든 `with Elasticsearch(...) as client:` 블록 안에서 아래 코드를 실행합니다. Kibana와 같은 설정으로 Python 실습용 인덱스 `rag-nori-nouns-python`을 생성합니다. [Nori 색인 스크립트](1.nori_index.py) 코드를 다시 실행하면 이미 생성한 Python 인덱스의 매핑을 조회합니다.

```python
index = "rag-nori-nouns-python"
body = {
    "settings": {
        "analysis": {
            "tokenizer": {
                "korean_tokenizer": {
                    "type": "nori_tokenizer",
                    "decompound_mode": "discard"
                }
            },
            "filter": {
                "noun_pos": {
                    "type": "nori_part_of_speech",
                    "stoptags": [
                        "E", "IC", "J", "MAG", "MAJ", "MM", "NP",
                        "SF", "SP", "SSC", "SSO", "SC", "SY", "SE",
                        "VA", "VCN", "VCP", "VV", "VX",
                        "XPN", "XR", "XSA", "XSV", "UNKNOWN", "UNA", "NA", "VSV",
                    ],
                },
            },
            "analyzer": {
                "korean_text": {
                    "type": "custom",
                    "tokenizer": "korean_tokenizer",
                    "filter": ["noun_pos", "lowercase"],
                }
            },
        }
    },
    "mappings": {
        "properties": {
            "docid": {"type": "keyword"},
            "title": {"type": "text", "analyzer": "korean_text"},
            "text": {"type": "text", "analyzer": "korean_text"},
        }
    },
}
if not client.indices.exists(index=index):
    client.indices.create(index=index, body=body)
pprint(client.indices.get_mapping(index=index).body, sort_dicts=False)
```

## 4. 인덱스 매핑 설정하기

매핑은 각 필드를 어떤 타입으로 저장하고 검색할지 정합니다. `docid`는 정확한 값으로 조회할 수 있도록 `keyword`로, `title`과 `text`는 단어로 검색할 수 있도록 `text`로 지정합니다.

```http
PUT /rag-python-mapping
{
  "mappings": {
    "properties": {
      "docid": { "type": "keyword" },
      "title": { "type": "text" },
      "text": { "type": "text" }
    }
  }
}

GET /rag-python-mapping/_mapping
```

`_mapping` 응답에서 세 필드의 타입을 확인합니다. 이 예제의 `title`과 `text`는 기본 분석기인 `standard`를 사용합니다.

## 5. Python에서 JSONL 문단 한 건 읽기

[MIRACL 코퍼스](dataset/corpus.jsonl)의 JSONL은 한 줄마다 JSON 객체 하나를 담고 있습니다. `json.loads()`로 한 줄을 Python 딕셔너리로 바꾸면 `row["docid"]`처럼 필드에 접근할 수 있습니다.

강의 폴더의 [1.read_corpus.py](1.read_corpus.py)를 저장소 루트에서 실행합니다. 스크립트는 자신의 위치를 기준으로 `dataset/corpus.jsonl`을 찾습니다.

```powershell
uv run --python 3.12 python ./10_14_1106_1127_retrieval/1.read_corpus.py
```

```python
import json
from pathlib import Path
from pprint import pprint

corpus = Path(__file__).resolve().parent / "dataset" / "corpus.jsonl"

with corpus.open(encoding="utf-8") as file:
    for line in file:
        row = json.loads(line)
        if row["docid"] == "64649#3":
            article_id, chunk_number = row["docid"].rsplit("#", 1)
            pprint({
                "title": row["title"],
                "article_id": article_id,
                "chunk_index": int(chunk_number),
                "text": row["text"],
            }, sort_dicts=False)
            break
```

출력에서 제목 **혼다 미나코**, 원본 문서 ID **64649**, 청크 번호 **3**을 확인합니다. 이 딕셔너리가 [검색용 문서 색인 실습](2.retrieval_indexing.md)에서 Elasticsearch에 넣을 문서의 출발점입니다.
