# 5강 · 벡터 검색 개론

**혼다 미나코의 출생 병원은 어디인가요?**

질문의 표현은 **출생 병원**이고, 근거 청크의 표현은 **나리마스 산원에서 태어났다**입니다. 질문과 청크를 각각 벡터로 표현하면, 이렇게 표현이 다른 두 텍스트의 관련성을 어떻게 비교할 수 있을까요?

## 1. 지난 시간 돌아보기 · BM25에서 근거 청크의 순위 바꾸기

[3강 BM25 검색 실습](3.bm25_search.md)에서는 제목과 본문을 검색하고, 나리마스 산원에서 태어났다는 근거 청크가 몇 위에 나오는지 확인했습니다.

| 검색 방식 | 근거 청크 순위 |
| --- | ---: |
| 제목과 본문에 기본 `multi_match` 적용 | 5위 |
| 검색 시 `병원`에 `산원`을 동의어로 추가 | 4위 |
| 동의어 적용 후 본문의 출생 장소 표현에 `bool.should`로 가산점 부여 | 1위 |
| 동의어 적용 후 제목과 본문에 흩어진 검색어를 `cross_fields`로 함께 반영 | 1위 |

### BM25의 한계

BM25는 질문과 문서에서 일치하는 토큰을 바탕으로 순위를 매깁니다. 표현이 다양해질수록 비슷한 뜻의 표현을 연결하는 **동의어 사전**과, 신조어나 상품명을 원하는 단위로 나누는 **사용자 사전**을 관리해야 합니다.

**색인용 사용자 사전에 새 단어를 등록해 토큰 분할 방식이 바뀌면, 해당 단어가 들어 있는 기존 문서를 재색인해야 합니다.** 이미 색인된 문서에는 등록 전의 토큰이 저장되어 있으므로, 재색인할 때 새 규칙으로 문서를 다시 분석합니다. [Elasticsearch 색인과 검색 시 분석](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/analysis-index-search-time.html)

3강에서는 `병원`과 `산원`이 이미 각각 하나의 토큰으로 분석됐기 때문에, 검색 시 동의어 규칙을 적용하는 것만으로 두 표현을 연결할 수 있었습니다.

#### 신조어를 사용자 사전에 등록하기

`얼죽아`는 ‘얼어 죽어도 아이스 아메리카노’의 줄임말입니다. 카페 후기에서 이 신조어를 검색할 때 여러 토큰으로 나뉘면, 기본 `match` 검색에는 일부 토큰만 겹치는 문서도 포함될 수 있습니다. 여기서는 `얼죽아` 전체를 하나의 검색 단위로 쓰도록 사용자 사전에 등록합니다.

Kibana Dev Tools에서 두 요청을 실행해 `tokens[].token`을 비교합니다. 기본 Nori가 어떤 토큰을 만드는지 보고, 사용자 사전을 적용하면 `얼죽아` 전체가 한 토큰으로 나오는지 확인합니다. [Elastic Nori 토크나이저 문서](https://www.elastic.co/docs/reference/elasticsearch/plugins/analysis-nori-tokenizer)

```http
POST /_analyze
{
  "tokenizer": "nori_tokenizer",
  "text": "얼죽아"
}

POST /_analyze
{
  "tokenizer": {
    "type": "nori_tokenizer",
    "user_dictionary_rules": ["얼죽아"]
  },
  "text": "얼죽아"
}
```

이런 한계를 보완하는 데 벡터 검색을 사용합니다. 질문과 청크를 벡터로 표현하면, 서로 다른 단어를 쓰더라도 의미가 비슷한 청크를 검색할 수 있습니다.

## 2. 임베딩 · 질문과 청크를 벡터로 표현하기

임베딩 모델은 텍스트를 숫자 벡터로 바꿉니다. 검색에 쓰는 임베딩 모델은 관련된 질문과 청크가 벡터 공간에서 가깝게 놓이도록 학습합니다.

> **질문** 이미 신청한 강의를 다른 강의로 바꿀 수 있나요?
>
> **근거 청크** 수강 정정 기간에는 신청 과목을 변경할 수 있다.

이 가상 학사 안내 예시에서 **강의를 바꾸다**와 **과목을 변경하다**는 다른 단어를 쓰면서 같은 행동을 가리킵니다. 벡터 검색은 질문과 청크의 벡터를 비교해 이런 관련성을 순위에 반영할 수 있습니다.

## 3. 색인과 검색 · 벡터는 언제 만드는가?

| 단계 | 처리 흐름 |
| --- | --- |
| **색인할 때** | 청크를 임베딩 모델에 넣어 벡터를 만들고, 원문과 함께 Elasticsearch에 저장합니다. |
| **검색할 때** | 질문을 같은 임베딩 모델로 벡터화하고, 저장된 청크 벡터 중 가까운 것을 찾습니다. |
| **검색 후** | 찾아낸 청크의 원문을 가져와 답변을 만드는 데 사용합니다. |

Elasticsearch에서 벡터를 저장하는 필드 타입은 `dense_vector`입니다. 코사인 유사도는 두 벡터의 방향이 얼마나 비슷한지 비교합니다. `knn` 검색은 설정된 유사도 기준으로 질문 벡터에 가까운 청크를 찾으며, `k`는 찾을 이웃의 개수입니다. [Elasticsearch 8.19 kNN 검색](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/knn-search.html)

## 4. REST API를 이용한 토큰화, 임베딩, 재순위

임베딩 리랭킹 서버 swagger : <https://labiv-llm.z.cs.kookmin.ac.kr/docs>

Python의 `requests.post()`로 임베딩·리랭킹 서버에 토큰화, 임베딩, 재순위를 요청합니다. 서버가 처리 결과를 JSON으로 반환하면 Python에서 `response.json()`으로 읽습니다.

각 Python 코드 블록을 통째로 `10_14_1106_1127_retrieval` 폴더에 표시된 파일명으로 저장합니다. 저장소 루트에 `.env`를 만들고 수업에서 안내받은 접속 정보를 채웁니다. `.gitignore`에 `.env`가 등록되어 있으며, `uv run --env-file .env`가 실행할 때 이 파일을 읽습니다.

```dotenv
LABIV_API_ID=
LABIV_API_PASSWORD=
```

`path`는 서버 주소 뒤에 붙일 API 경로입니다. `auth`로 HTTP Basic 인증 정보를 보내고, `json`으로 Python 딕셔너리를 JSON 요청 본문에 담습니다. 아래 실행 명령은 모두 `2609_kookmin_rag` 저장소 루트에서 실행합니다.

### 임베딩 설명

예제 파일은 [5.embeddings.py](5.embeddings.py)입니다.

```python
import os

import requests

base_url = "https://labiv-llm.z.cs.kookmin.ac.kr"
ID = os.environ["LABIV_API_ID"]
PASSWORD = os.environ["LABIV_API_PASSWORD"]

path = "/v1/embeddings"
payload = {
    "model": "bge-m3",
    "input": [
      "서울은 대한민국의 수도이다.",
      "The capital of France is Paris."
    ]
}

response = requests.post(
    f"{base_url}{path}", auth=(ID, PASSWORD), json=payload, timeout=60

response.raise_for_status()

```

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests python ./10_14_1106_1127_retrieval/5.embeddings.py
```

위 예제는 `input`에 서울 문장과 파리 문장을 담아 한 번에 보냅니다. 응답의 `data`에는 문장별로 벡터가 하나씩 들어 있습니다. 같은 방식으로 색인할 문서 청크도 여러 개씩 묶어 보낼 수 있고, 서버가 배치 추론을 지원하면 처리량도 높일 수 있습니다.

- **검색할 때는 단건 입력**으로 사용자 질문이 들어오는 즉시 벡터를 요청합니다. 같은 모델로 같은 질문을 다시 임베딩할 때는 저장한 벡터를 재사용할 수 있습니다. 캐시는 클라이언트와 서버 양쪽에 둘 수 있습니다.
- **색인할 때는 배치 입력**으로 준비된 문서 청크 여러 개를 배열에 담아 한 번에 요청합니다.

#### 두 질문의 코사인 유사도 계산하기

두 질문을 한 요청으로 임베딩한 뒤, **두 벡터의 내적을 각 벡터 길이의 곱으로 나눠** 코사인 유사도를 계산합니다. 점수가 1에 가까울수록 두 벡터의 방향이 비슷합니다. 아래 코드를 `5.cosine_similarity.py`로 저장합니다.

```python
import os
from math import hypot, sumprod

import requests

base_url = "https://labiv-llm.z.cs.kookmin.ac.kr"
ID = os.environ["LABIV_API_ID"]
PASSWORD = os.environ["LABIV_API_PASSWORD"]


def cosine_similarity(left, right):
    dot_product = sumprod(left, right)
    return dot_product / (hypot(*left) * hypot(*right))


path = "/v1/embeddings"
questions = [
    "혼다 미나코의 출생 병원은 어디인가요?",
    "혼다 미나코의 출생지는 어디인가요?",
]
payload = {"model": "bge-m3", "input": questions}

response = requests.post(
    f"{base_url}{path}", auth=(ID, PASSWORD), json=payload, timeout=60
)
response.raise_for_status()
vectors = {item["index"]: item["embedding"] for item in response.json()["data"]}
first_vector = vectors[0]
second_vector = vectors[1]

similarity = cosine_similarity(first_vector, second_vector)

print(f"코사인 유사도: {similarity:.4f}")
```

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests python ./10_14_1106_1127_retrieval/5.cosine_similarity.py
```

### 클라이언트에서 질문 벡터 캐시하기

`5.embedding_cache.py`를 실행합니다. 첫 호출은 서버에서 받은 벡터를 모델명과 질문을 키로 삼아 저장합니다. 두 번째 호출은 저장된 벡터를 꺼내므로 API 요청은 한 번만 발생합니다. 메모리에 벡터를 최대 128개까지 저장하며, 한도를 넘으면 가장 오래 사용하지 않은 항목을 지웁니다(LRU).

```python
import os
from collections import OrderedDict

import requests

BASE_URL = "https://labiv-llm.z.cs.kookmin.ac.kr"
ID = os.environ["LABIV_API_ID"]
PASSWORD = os.environ["LABIV_API_PASSWORD"]
MODEL = "bge-m3"
MAX_CACHE_SIZE = 128

embedding_cache = OrderedDict()


def embed(text):
    key = (MODEL, text)
    if key in embedding_cache:
        print(f"캐시 적중 · {text}")
        embedding_cache.move_to_end(key)
        return embedding_cache[key]

    print(f"서버 요청 · {text}")
    path = "/v1/embeddings"
    payload = {"model": MODEL, "input": text}
    response = requests.post(
        f"{BASE_URL}{path}", auth=(ID, PASSWORD), json=payload, timeout=60
    )
    response.raise_for_status()
    vector = response.json()["data"][0]["embedding"]
    embedding_cache[key] = vector
    if len(embedding_cache) > MAX_CACHE_SIZE:
        embedding_cache.popitem(last=False)
    return vector


if __name__ == "__main__":
    question = "혼다 미나코의 출생 병원은 어디인가요?"

    first_vector = embed(question)
    second_vector = embed(question)

    print(f"벡터 차원: {len(first_vector)}")
    print(f"두 벡터가 같은가요? {first_vector == second_vector}")
```

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests python ./10_14_1106_1127_retrieval/5.embedding_cache.py
```

### 문장의 토큰 확인하기

**얼죽아**는 ‘얼어 죽어도 아이스 아메리카노’의 줄임말입니다. 토큰 어휘에 표현 전체가 없으면 ‘얼’, ‘죽’, ‘아’처럼 한 글자씩 나뉠 수 있습니다. `with_pieces`를 켜고 **얼죽아**가 실제로 어떻게 나뉘는지 확인합니다. [Hugging Face 토큰화 문서](https://huggingface.co/docs/transformers/en/tokenizer_summary)

사람도 낯선 표현을 일상적인 말로 풀어 주면 뜻을 이해하기 쉽습니다. 원문, 풀어 쓴 문장, 기준 문장의 토큰 조각을 살펴보고 세 문장 쌍의 코사인 유사도를 비교합니다. 특히 풀어 쓴 뒤 기준 문장과의 유사도가 어떻게 달라지는지 확인합니다.

예제 파일은 [5.tokenize.py](5.tokenize.py)입니다.

```python
import os
from math import hypot, sumprod

import requests

base_url = "https://labiv-llm.z.cs.kookmin.ac.kr"
ID = os.environ["LABIV_API_ID"]
PASSWORD = os.environ["LABIV_API_PASSWORD"]

original = "난 얼죽아야."
rewritten = "난 날씨가 추워도 아이스 아메리카노를 마셔."
reference = "한겨울에도 따뜻한 커피보다 아이스 아메리카노를 고른다."
sentences = [original, rewritten, reference]


def cosine_similarity(left, right):
    dot_product = sumprod(left, right)
    return dot_product / (hypot(*left) * hypot(*right))


path = "/v1/tokenize"
for sentence in sentences:
    payload = {"model": "bge-m3", "content": sentence, "with_pieces": True}
    response = requests.post(
        f"{base_url}{path}", auth=(ID, PASSWORD), json=payload, timeout=60
    )
    response.raise_for_status()
    print(f"\n토큰화: {sentence}")
    pieces = [token["piece"] for token in response.json()["tokens"]]
    print(pieces)

path = "/v1/embeddings"
payload = {"model": "bge-m3", "input": sentences}
response = requests.post(
    f"{base_url}{path}", auth=(ID, PASSWORD), json=payload, timeout=60
)
response.raise_for_status()
vectors = {item["index"]: item["embedding"] for item in response.json()["data"]}

print("\n코사인 유사도")
print(f"원문 ↔ 풀어 쓴 문장: {cosine_similarity(vectors[0], vectors[1]):.4f}")
print(f"원문 ↔ 기준 문장: {cosine_similarity(vectors[0], vectors[2]):.4f}")
print(f"풀어 쓴 문장 ↔ 기준 문장: {cosine_similarity(vectors[1], vectors[2]):.4f}")
```

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests python ./10_14_1106_1127_retrieval/5.tokenize.py
```

### 질문에 맞게 후보 문서 재정렬하기

`query`에 질문을, `documents`에 후보 문서를 넣습니다. `bge-reranker-v2-m3`는 질문과 각 후보의 관련도를 매기고, `top_n`에 지정한 개수만큼 결과를 반환합니다. 세 문장 중 어떤 두 문장이 돌아오고 서울이 나오는 문장이 몇 위인지 확인합니다.

관련도 점수에 sigmoid를 적용하면 0과 1 사이의 값으로 바뀝니다.

파일명은 `5.rerank.py`입니다.

```python
import os

import requests

base_url = "https://labiv-llm.z.cs.kookmin.ac.kr"
ID = os.environ["LABIV_API_ID"]
PASSWORD = os.environ["LABIV_API_PASSWORD"]

path = "/v1/rerank"
payload = {
    "model": "bge-reranker-v2-m3",
    "query": "대한민국의 수도는 어디인가?",
    "documents": [
      "서울은 대한민국의 수도이다.",
      "파리는 프랑스의 수도이다.",
      "고양이는 포유류이다."
    ],
    "top_n": 2,
}

response = requests.post(
    f"{base_url}{path}", auth=(ID, PASSWORD), json=payload, timeout=60
)
response.raise_for_status()
print(response.json())
```

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests python ./10_14_1106_1127_retrieval/5.rerank.py
```

## 5. Elasticsearch를 이용한 벡터 검색

### Kibana에서 kNN 요청 구조 확인하기

Kibana Dev Tools에서 아래 요청을 순서대로 실행합니다. 계산을 살펴보기 위해 직접 만든 3차원 벡터를 사용합니다. 문서 A는 질문 벡터와 방향이 같고, 문서 B는 수직입니다.

```http
PUT /knn-lecture-demo
{
  "mappings": {
    "properties": {
      "text": { "type": "text" },
      "embedding": {
        "type": "dense_vector",
        "dims": 3,
        "similarity": "cosine"
      }
    }
  }
}

PUT /knn-lecture-demo/_doc/A?refresh=true
{
  "text": "문서 A",
  "embedding": [1.0, 0.0, 0.0]
}

PUT /knn-lecture-demo/_doc/B?refresh=true
{
  "text": "문서 B",
  "embedding": [0.0, 1.0, 0.0]
}

POST /knn-lecture-demo/_search
{
  "knn": {
    "field": "embedding",
    "query_vector": [1.0, 0.0, 0.0],
    "k": 2,
    "num_candidates": 10
  },
  "size": 2,
  "_source": ["text"]
}
```

`query_vector`를 `[0.0, 1.0, 0.0]`으로 바꿔 다시 검색하고, 문서 A와 B의 순위가 어떻게 바뀌는지 확인합니다.

```http
POST /knn-lecture-demo/_search
{
```

### Python에서 임베딩 API와 kNN 검색 연결하기

4절에서 사용한 **`bge-m3` REST API**로 문서 청크와 검색 질문을 임베딩합니다. 문서 청크는 여러 개씩 묶어 API에 보내고, 받은 1,024차원 벡터를 새 인덱스 `rag-miracl-ko-bge-m3`의 `embedding` 필드에 저장합니다. 검색할 때도 같은 API로 질문 벡터를 만들어 `knn.query_vector`에 넘깁니다.

Elasticsearch는 저장된 벡터와 질문 벡터를 비교해 코사인 유사도가 높은 청크를 반환합니다. `k`는 찾을 이웃의 수이고, `num_candidates`는 각 샤드에서 탐색할 후보 수입니다. [Elasticsearch 8.19 kNN 검색](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/knn-search.html)

4절에서 채운 `.env`에 로컬 Elasticsearch의 `elastic` 계정 비밀번호를 `ES_PASSWORD`로 추가합니다. 두 예제 파일은 학생용 저장소의 `10_14_1106_1127_retrieval` 폴더에 둡니다.

[5.index_bge_m3.py](5.index_bge_m3.py)는 문서 청크를 배치로 임베딩해 Elasticsearch에 색인합니다.

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests --with "elasticsearch>=8.19,<9" python ./10_14_1106_1127_retrieval/5.index_bge_m3.py
```

[5.vector_search.py](5.vector_search.py)는 질문을 임베딩하고, 색인이 끝난 인덱스에서 kNN 검색을 실행합니다.

Kibana에서 작성한 검색 JSON을 Python에서는 `client.search(index=INDEX, body={...})`의 `body`에 넣습니다. `query_vector`에는 API에서 받은 질문 벡터를 전달합니다.

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests --with "elasticsearch>=8.19,<9" python ./10_14_1106_1127_retrieval/5.vector_search.py
```

기본 질문은 **“혼다 미나코의 출생 병원은 어디인가요?”**입니다.

### 제목과 본문을 함께 임베딩해 색인하기

혼다 미나코의 출생 병원이 적힌 청크는 본문에 인물 이름이 없습니다. 각 청크 앞에 제목을 붙여 임베딩하면 해당 청크가 어느 인물이나 주제에 관한 내용인지 함께 전달할 수 있습니다.

청크에 문서 제목을 함께 넣으면 본문에 빠진 문맥을 보완할 수 있습니다. 다만 제목을 붙일수록 처리할 토큰이 늘어나므로, 대규모 문서를 색인할 때는 처리 시간과 비용도 고려해야 합니다. 제목이 내용을 잘 설명하는지, 본문만으로 문맥이 충분한지에 따라 적용 방식을 정합니다. 이번 실습에서는 제목을 붙였을 때 검색 결과가 어떻게 달라지는지 비교합니다.

[5.index_bge_m3_title_body.py](5.index_bge_m3_title_body.py)는 임베딩 입력을 아래처럼 바꾸고, 새 인덱스 `rag-miracl-ko-bge-m3-title-body`에 색인합니다. 문서 ID와 저장하는 제목·본문은 앞선 색인과 같으며, 같은 제목을 각 청크 앞에 한 번씩 붙여 벡터를 만듭니다.

```python
INDEX = "rag-miracl-ko-bge-m3-title-body"

vectors = embed([
    f"{passage['title']}\n{passage['text']}"
    for passage in batch
])
```

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests --with "elasticsearch>=8.19,<9" python ./10_14_1106_1127_retrieval/5.index_bge_m3_title_body.py
```
