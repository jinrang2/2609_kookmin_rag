# 6강 · 벡터 검색

[5강 토큰화와 임베딩](5.tokenize.md)에서 사용한 임베딩 API로 Elasticsearch kNN 검색을 실행합니다.

## 1. Elasticsearch를 이용한 벡터 검색

### Kibana에서 kNN 요청 구조 확인하기

Kibana Dev Tools에서 아래 요청을 순서대로 실행합니다. 계산을 살펴보기 위해 직접 만든 3차원 벡터를 사용합니다. 문서 A는 질문 벡터와 방향이 같고, 문서 B는 수직입니다.

```http
PUT /knn-lecture-demo
{
  "mappings": {
    "properties": {
      "text": { "type": "text" },
      "embedding": {
        "type": "dense_vector",
        "dims": 3,
        "similarity": "cosine"
      }
    }
  }
}

PUT /knn-lecture-demo/_doc/A?refresh=true
{
  "text": "문서 A",
  "embedding": [1.0, 0.0, 0.0]
}

PUT /knn-lecture-demo/_doc/B?refresh=true
{
  "text": "문서 B",
  "embedding": [0.0, 1.0, 0.0]
}

POST /knn-lecture-demo/_search
{
  "knn": {
    "field": "embedding",
    "query_vector": [1.0, 0.0, 0.0],
    "k": 2,
    "num_candidates": 10
  },
  "size": 2,
  "_source": ["text"]
}
```

`query_vector`를 `[0.0, 1.0, 0.0]`으로 바꿔 다시 검색하고, 문서 A와 B의 순위가 어떻게 바뀌는지 확인합니다.

```http
POST /knn-lecture-demo/_search
{
  "knn": {
    "field": "embedding",
    "query_vector": [0.0, 1.0, 0.0],
    "k": 2,
    "num_candidates": 10
  },
  "size": 2,
  "_source": ["text"]
}
```

### Python에서 임베딩 API와 kNN 검색 연결하기

5강에서 사용한 **`bge-m3` REST API**로 문서 청크와 검색 질문을 임베딩합니다. 문서 청크는 여러 개씩 묶어 API에 보내고, 받은 1,024차원 벡터를 새 인덱스 `rag-miracl-ko-bge-m3`의 `embedding` 필드에 저장합니다. 검색할 때도 같은 API로 질문 벡터를 만들어 `knn.query_vector`에 넘깁니다.

Elasticsearch는 저장된 벡터와 질문 벡터를 비교해 코사인 유사도가 높은 청크를 반환합니다. `k`는 찾을 이웃의 수이고, `num_candidates`는 각 샤드에서 탐색할 후보 수입니다. [Elasticsearch 8.19 kNN 검색](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/knn-search.html)

5강에서 채운 `.env`에 로컬 Elasticsearch의 `elastic` 계정 비밀번호를 `ES_PASSWORD`로 추가합니다. 두 예제 파일은 학생용 저장소의 `10_14_1106_1127_retrieval` 폴더에 둡니다.

[6.index_bge_m3.py](6.index_bge_m3.py)는 문서 청크를 배치로 임베딩해 Elasticsearch에 색인합니다.

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests --with "elasticsearch>=8.19,<9" python ./10_14_1106_1127_retrieval/6.index_bge_m3.py
```

[6.vector_search.py](6.vector_search.py)는 질문을 임베딩하고, 색인이 끝난 인덱스에서 kNN 검색을 실행합니다.

Kibana에서 작성한 검색 JSON을 Python에서는 `client.search(index=INDEX, body={...})`의 `body`에 넣습니다. `query_vector`에는 API에서 받은 질문 벡터를 전달합니다.

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests --with "elasticsearch>=8.19,<9" python ./10_14_1106_1127_retrieval/6.vector_search.py
```

기본 질문은 **“혼다 미나코의 출생 병원은 어디인가요?”**입니다.

### 다른 질문으로 검색 결과 비교하기

아래 세 질문은 실습 데이터셋의 `queries.jsonl`에서 골랐습니다. `--question`으로 질문을 바꿔 검색하고, 가장 높은 점수를 받은 1위 청크의 문서 ID와 `_score`를 기록합니다. 본문에 질문의 답이 있는지도 확인합니다.

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests --with "elasticsearch>=8.19,<9" python ./10_14_1106_1127_retrieval/6.vector_search.py --question "수원지로부터 필요한 수량을 취입하는 과정은 무엇인가요?"
```

| 질문 | 1위 청크 ID | 1위 점수 | 본문에 답이 있는가 |
| --- | --- | --- | --- |
| 수원지로부터 필요한 수량을 취입하는 과정은 무엇인가요? | `544622#5` | 0.878864 | 있음: 취수 |
| 혼다 미나코의 출생 병원은 어디인가요? | `64649#0` | 0.783890 | 없음: 인물 소개 |
| 인간의 몸에는 몇 개의 뼈가 있는가? | `1448543#2` | 0.886784 | 있음: 성인 206개, 신생아 270개 |

### 제목과 본문을 함께 임베딩해 색인하기

혼다 미나코의 출생 병원이 적힌 청크는 본문에 인물 이름이 없습니다. 각 청크 앞에 제목을 붙여 임베딩하면 해당 청크가 어느 인물이나 주제에 관한 내용인지 함께 전달할 수 있습니다.

청크에 문서 제목을 함께 넣으면 본문에 빠진 문맥을 보완할 수 있습니다. 다만 제목을 붙일수록 처리할 토큰이 늘어나므로, 대규모 문서를 색인할 때는 처리 시간과 비용도 고려해야 합니다. 제목이 내용을 잘 설명하는지, 본문만으로 문맥이 충분한지에 따라 적용 방식을 정합니다. 이번 실습에서는 제목을 붙였을 때 검색 결과가 어떻게 달라지는지 비교합니다.

[6.index_bge_m3_title_body.py](6.index_bge_m3_title_body.py)는 임베딩 입력을 아래처럼 바꾸고, 새 인덱스 `rag-miracl-ko-bge-m3-title-body`에 색인합니다. 문서 ID와 저장하는 제목·본문은 앞선 색인과 같으며, 같은 제목을 각 청크 앞에 한 번씩 붙여 벡터를 만듭니다.

```python
INDEX = "rag-miracl-ko-bge-m3-title-body"

vectors = embed([
    f"{passage['title']}\n{passage['text']}"
    for passage in batch
])
```

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests --with "elasticsearch>=8.19,<9" python ./10_14_1106_1127_retrieval/6.index_bge_m3_title_body.py
```

### 같은 세 질문으로 점수 다시 확인하기

색인이 끝나면 **‘다른 질문으로 검색 결과 비교하기’를 한 번 더 실행**합니다. 이번에는 `--index rag-miracl-ko-bge-m3-title-body`를 지정하고, 같은 세 질문으로 검색합니다.

**실행 명령어**

```shell
uv run --env-file .env --python 3.12 --with requests --with "elasticsearch>=8.19,<9" python ./10_14_1106_1127_retrieval/6.vector_search.py --index rag-miracl-ko-bge-m3-title-body --question "수원지로부터 필요한 수량을 취입하는 과정은 무엇인가요?"

uv run --env-file .env --python 3.12 --with requests --with "elasticsearch>=8.19,<9" python ./10_14_1106_1127_retrieval/6.vector_search.py --index rag-miracl-ko-bge-m3-title-body --question "혼다 미나코의 출생 병원은 어디인가요?"

uv run --env-file .env --python 3.12 --with requests --with "elasticsearch>=8.19,<9" python ./10_14_1106_1127_retrieval/6.vector_search.py --index rag-miracl-ko-bge-m3-title-body --question "인간의 몸에는 몇 개의 뼈가 있는가?"
```

각 질문의 1위 청크와 `_score`를 다시 기록하고, 앞선 본문 색인 결과와 비교합니다. 1위 청크의 본문에 답이 있는지도 확인합니다.

2026년 11월 19일 실습 서버의 `bge-m3`로 실행한 결과입니다. 두 인덱스에는 같은 코퍼스 1,000개가 들어 있으며, 검색 설정은 `k=5`, `num_candidates=50`입니다. 점수는 Elasticsearch 응답의 `_score`를 소수점 여섯 자리로 표시했습니다.

| 질문 | 본문 색인 1위 ID | 점수 | 본문에 답이 있는가 | 제목+본문 색인 1위 ID | 점수 | 본문에 답이 있는가 |
| --- | --- | --- | --- | --- | --- | --- |
| 수원지로부터 필요한 수량을 취입하는 과정은 무엇인가요? | `544622#5` | 0.878864 | 있음: 취수 | `544622#5` | 0.852907 | 있음: 취수 |
| 혼다 미나코의 출생 병원은 어디인가요? | `64649#0` | 0.783890 | 없음: 인물 소개 | `64649#3` | 0.844190 | 있음: 나리마스 산원 |
| 인간의 몸에는 몇 개의 뼈가 있는가? | `1448543#2` | 0.886784 | 있음: 성인 206개, 신생아 270개 | `1448543#2` | 0.896724 | 있음: 성인 206개, 신생아 270개 |

혼다 미나코 질문에서는 출생 병원 근거 청크 `64649#3`의 순위도 비교합니다. 점수 변화와 함께 정답이 담긴 청크가 위로 올라왔는지 살펴봅니다.
