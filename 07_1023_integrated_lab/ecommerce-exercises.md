# 10월 23일 전반기 종합 실습: 주문 데이터 검색과 분석

Kibana의 `Sample eCommerce orders`를 사용해 주문을 검색하고, 통계를 계산하고, 결과를 검증합니다. 요구사항과 출력 형식을 읽고 필요한 Elasticsearch 요청을 작성합니다. Python을 활용한 조회와 파일 처리는 선택사항입니다.

## 진행 방법

- Kibana Dev Tools에서 풀이할 수 있습니다. Python 사용 여부는 자유롭게 선택합니다.
- AI가 제안한 요청도 직접 실행하고, 요구사항 충족 여부와 결과를 확인합니다.
- 요구사항을 만족하는 여러 풀이를 사용할 수 있습니다.

| 교시 | 진행 방식 |
| --- | --- |
| 1교시 | 오픈북 실습. 강의자료와 공식 문서를 참고해 직접 풀이합니다. AI는 2교시부터 사용합니다. |
| 2교시 | AI 사용을 허용합니다. 풀이를 이어가며 요청을 실행하고 결과를 검증합니다. |
| 3교시 | 강사와 함께 문제를 풀이합니다. 요청을 작성한 이유와 실행 결과를 살펴보고, 자신의 풀이와 비교합니다. |

### Python 예제 실행 (선택)

같은 폴더의 [es.py](es.py)는 Elasticsearch 접속을 확인하고 샘플 주문 10건을 검색합니다. `uv`가 Python과 Elasticsearch 8.19용 클라이언트를 준비합니다. Elasticsearch 서버는 수업에서 제공하는 서버에 접속합니다.

학생용 저장소 `2609_kookmin_rag` 루트에서 실행하세요.

```sh
uv run --script ./07_1023_integrated_lab/es.py
```

`es.py`에서 주소, 사용자 이름, 비밀번호를 수업에서 받은 값으로 바꾸세요.

```python
es = Elasticsearch(
    "https://localhost:9200",
    basic_auth=("elastic", "YOUR_PASSWORD"),
    verify_certs=False,
    ssl_show_warn=False,
)
```

`verify_certs=False`는 HTTPS 인증서 검증을 끄고, `ssl_show_warn=False`는 인증서 검증 관련 경고를 숨깁니다.

`es.py`의 `query` 값을 바꾸면 다른 검색 조건을 실행할 수 있습니다. `size=10`은 이번 요청으로 가져올 최대 문서 수이며, 조건에 맞는 전체 주문 수는 별도로 출력됩니다.

## 연습문제 2. 검색 결과 구성

### 2-1. 여러 조건을 만족하는 주문 상세 조회

사용할 필드: 국가 `geoip.country_iso_code`, 금액 `taxful_total_price`, 상품명 `products.product_name`, 주문번호 `order_id`, 주문일 `order_date`.

고객지원 담당자가 상품명에 `basic`과 `shirt`가 모두 포함된 주문을 찾고 있습니다. `basic`과 `shirt`는 주문에 포함된 상품명들에서 검색하며, 동일한 상품 하나에 함께 등장해야 한다는 조건은 두지 않습니다.

- 국가 코드가 `US`인 주문만 대상으로 합니다.
- 주문 전체 금액은 50 이상 200 미만입니다.
- 금액이 큰 순서로 정렬하고, 금액이 같으면 주문번호 오름차순으로 정렬합니다.
- 최대 10건을 출력합니다.
- 출력 필드는 주문번호, 국가, 주문일, 주문 전체 금액, 상품명 목록입니다.

검색된 각 주문이 요구조건을 만족하는지 확인합니다.

### 2-2. 검색어 일부만 일치하는 주문까지 확장

사용할 필드: 국가 `geoip.country_iso_code`, 금액 `taxful_total_price`, 상품명 `products.product_name`, 주문번호 `order_id`, 검색 점수 `_score`.

국가 코드가 `US`이고 주문금액이 50 이상 200 미만인 주문을 대상으로 합니다. 상품명에 `basic` 또는 `shirt` 중 하나 이상이 포함된 주문을 검색하세요. 두 단어가 모두 포함된 주문에는 더 높은 검색 점수를 부여하도록 구성합니다.

- 검색 점수가 높은 순서로 최대 10건을 출력합니다.
- 각 행에 주문번호, 상품명 목록, 검색 점수, 일치한 검색어 수를 표시합니다.
- 2-1의 조건을 만족하는 전체 주문번호 집합과 이번 조건의 전체 주문번호 집합을 구합니다. 상위 10건만으로 집합을 비교하지 않습니다.

두 결과 집합의 공통 주문 수와 이번에 추가된 주문 수를 구합니다. 점수를 높이기 위해 사용한 조건을 설명하고, 상품명과 문서별 점수 차이도 관찰합니다.

- 평균이 같으면 국가 코드 오름차순으로 정렬합니다.

| 국가 | 주문 건수 | 주문금액 합계 | 평균 주문금액 |
| --- | ---: | ---: | ---: |
| 실행 결과 | 실행 결과 | 실행 결과 | 실행 결과 |

국가별 집계 결과를 충분히 확보해 상위 국가가 누락되지 않았는지 확인합니다.

### 4-2. 주문 건수 순위와 주문금액 순위 비교

사용할 필드: 국가 `geoip.country_iso_code`, 금액 `taxful_total_price`.

같은 기간에서 국가별 주문 건수 상위 5개와 주문금액 합계 상위 5개를 각각 구하세요. 동률은 국가 코드 오름차순으로 처리합니다.

두 목록을 비교해 공통 국가, 주문 건수 상위에만 있는 국가, 주문금액 상위에만 있는 국가를 구분합니다. 한 행에 국가, 주문 건수, 주문금액 합계, 두 순위를 기록하고, 상위 목록 밖의 순위는 빈칸으로 둡니다. 비교는 결과를 직접 대조하거나 코드로 처리할 수 있습니다.

순위 차이가 나타난 국가의 평균 주문금액을 확인합니다. 두 상위 목록이 같다면 순서 차이를 비교하고, 순서도 같으면 그 사실을 확인합니다.

## 연습문제 5. 시간 비교와 대시보드

### 5-1. 일별 실적 비교와 대시보드 만들기

사용할 필드: 주문일 `order_date`, 금액 `taxful_total_price`, 국가 `geoip.country_iso_code`.

기간 A와 기간 B의 일별 주문 건수와 주문금액 합계를 구하세요. UTC 기준으로 계산하고 주문이 없는 날도 날짜, 주문 수 0, 금액 0으로 출력합니다.

각 기간에 대해 총주문 수, 총주문금액, 일평균 주문금액을 계산합니다. 일평균의 분모는 주문이 있었던 날의 수가 아니라 기간 전체인 7일입니다.

일별 금액을 합산한 값과 기간 전체 금액을 비교해 검증합니다. 기간 A 대비 B의 금액 증감액과 증감률도 계산합니다. A의 금액이 0이면 증감률을 계산할 수 없다고 표시합니다.

Kibana에서 `주문 분석`이라는 대시보드를 만들고 다음 내용을 표시하세요. 샘플에 포함된 완성 대시보드 대신 새 대시보드를 만듭니다.

| 표시할 내용 | 차트 종류 | 설정 |
| --- | --- | --- |
| 전체 현황 | Metric (숫자 지표) 3개 | 주문 건수, 주문금액 합계, 평균 주문금액을 각각 표시 |
| 일별 추이 | Line (꺾은선 차트) | 가로축은 `order_date`의 1일 간격, 세로축은 `taxful_total_price`의 합계 |
| 국가별 비교 | Bar (가로 막대 차트) | 세로축은 `geoip.country_iso_code`, 가로축은 `taxful_total_price`의 합계. 금액이 큰 국가부터 위에 표시 |

시간 필드는 `order_date`를 사용하고, 날짜 범위는 공통 분석 기간으로 설정하세요. 일별 차트의 날짜 구분은 쿼리와 같은 UTC 기준으로 맞추세요. 각 차트의 제목에는 무엇을 세거나 합산한 값인지 적으세요.

대시보드의 주문 건수와 주문금액 합계가 같은 기간의 쿼리 결과와 일치하는지 확인하세요.

### 5-2. 금액 변화와 비중 변화 구분

사용할 필드: 주문일 `order_date`, 금액 `taxful_total_price`, 국가 `geoip.country_iso_code`.

공통 분석 기간에서 미국(`US`)의 일별 주문금액과 전체 국가의 일별 주문금액을 구하고, 미국(`US`)의 전체 대비 비중을 계산하세요.

| 날짜 | 전체 금액 | 미국 금액 | 미국 비중 | 미국 금액 전일 대비 증감액 | 비중 전일 대비 증감(%p) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 실행 결과 | 실행 결과 | 실행 결과 | 실행 결과 | 실행 결과 | 실행 결과 |

미국(`US`)의 금액은 전날보다 감소했지만 비중은 증가한 날을 찾습니다. 해당 날짜가 없으면 0건으로 보고합니다. 첫날의 전일 비교 값과 전체 금액이 0인 날의 비중은 빈칸으로 둡니다.

해당 현상이 가능한 이유를 전체 금액과 국가 금액의 관계로 설명합니다.

5-1에서 만든 대시보드로 다음 상황을 확인하세요.

1. 날짜 범위를 기간 A와 기간 B로 각각 바꾸세요. 전체 주문금액이 앞서 계산한 각 기간의 합계와 일치하는지 확인하세요.
2. 날짜 범위를 공통 분석 기간으로 되돌리고 국가 코드가 `US`인 주문만 보이도록 필터를 적용하세요. 전체 현황의 숫자와 일별 차트가 미국(`US`)의 값으로 바뀌는지 확인하세요.
3. 같은 날짜와 국가 조건으로 쿼리를 실행하세요. 대시보드의 주문 건수와 주문금액 합계를 쿼리 결과와 비교하세요.
4. 국가 필터를 해제하고 전체 국가의 값으로 돌아오는지 확인하세요.

## 연습문제 6. 추출과 결과 검증

### 6-1. 주문 전체를 조회하고 검증

사용할 필드: 국가 `geoip.country_iso_code`, 주문번호 `order_id`, 금액 `taxful_total_price`.

공통 분석 기간에서 국가 코드가 `US`인 주문 전체를 여러 페이지로 나누어 조회하세요. 한 번의 요청으로 가져오는 문서는 최대 100건으로 제한합니다. 다음 두 방식 중 하나를 선택합니다.

- 조회 결과 기반: Dev Tools 등에서 페이지별 요청과 응답을 기록하고, 전체 주문을 빠짐없이 조회했는지 검증합니다.
- 파일 기반: Python 등으로 전체 주문을 JSONL로 저장합니다. 원본 문서의 필드를 유지하고 한 줄에 주문 하나를 기록한 뒤, 파일을 다시 읽어 검증합니다.

조회 결과 또는 파일에서 다음 값을 계산하고 Elasticsearch에서 같은 조건으로 얻은 값과 비교합니다.

| 검증 항목 | Elasticsearch 집계 결과 | 전체 조회 결과 또는 파일에서 계산한 값 |
| --- | ---: | ---: |
| 주문 건수 | 실행 결과 | 실행 결과 |
| 주문금액 합계 | 실행 결과 | 실행 결과 |

고유 주문번호 수와 중복 주문번호도 별도로 출력합니다. 금액 비교에는 절대 오차 `0.01` 이하를 허용합니다. 추출 도중 원본이 바뀌는 상황에서 일관된 결과를 얻기 위한 방법을 설명합니다.

사용한 페이지 처리와 정렬 기준을 확인합니다. 데이터가 100건 이하면 페이지 크기를 10건으로 줄여 여러 페이지를 처리합니다.

### 6-2. 주문 단위 데이터를 상품 행 단위로 변환

사용할 필드: 주문번호 `order_id`, 고객 `customer_id`, 주문일 `order_date`, 금액 `taxful_total_price`, 상품 목록 `products`.

6-1에서 조회한 주문 또는 저장한 JSONL을 사용합니다. 각 주문의 상품 목록을 상품 객체 하나당 한 행으로 펼쳐 표 또는 CSV를 만드세요. 파일 처리 없이 풀이하는 경우에는 상품이 여러 개 있는 주문을 포함해 최대 10건의 주문을 선택하고, 선택한 주문번호를 기록합니다.

표 또는 CSV에는 주문번호, 고객 ID, 주문일, 주문 전체 금액, 상품 ID, 상품명, 상품 수량을 포함합니다. 상품 수량은 원본 상품 객체의 필드를 확인해 사용하고, 해당 필드가 없으면 빈칸으로 둡니다.

다음을 계산하고 비교합니다.

1. 분석 대상 주문 수, 펼친 상품 행 수, 펼친 결과의 고유 주문번호 수.
2. 분석 대상 주문에서 합산한 주문 전체 금액.
3. 펼친 모든 행에서 주문 전체 금액을 단순 합산한 값.
4. 펼친 결과에서 주문번호별로 주문 전체 금액을 한 번만 반영한 합계.

상품 행 수와 상품 수량 합계의 차이, 상품 행별로 주문 전체 금액을 더했을 때 생기는 문제를 설명합니다. 상품 목록이 비어 있는 주문이 있으면 건수와 처리 방식을 확인합니다.

숫자는 계산 중 원래 정밀도를 유지하고, 표에 표시할 때 금액은 소수 둘째 자리까지 반올림합니다. `%`와 `%p`를 구분해 표시합니다.
